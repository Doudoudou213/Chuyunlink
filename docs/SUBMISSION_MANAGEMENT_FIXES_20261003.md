# 投稿管理、标题与资源关联修复

## 基线与范围

基于已整合视觉及纸上换景动效的 `1891592`，在独立工作树 `ChuLink-Legacy-submission-fixes-20261003`、分支 `codex/fix-submission-management-20261003` 开发。原后端、视觉和整合工作树均不改动；本次没有推送、合并、部署或操作生产数据。

## 三个使用变化

1. **通过之后继续管理**：投稿工作台增加待审核、已通过、已撤回状态切换，按标题或完整投稿编号搜索并翻页；审核成功可直接管理该条投稿。已通过投稿可以改绑、取消关联或撤回公开展示。撤回必须填写原因，保留原始资料、审核记录和已发积分；不会重新进入发积分流程。个人主页显示已撤下与处理原因。
2. **用户自己起标题**：在采集页笔记区域增加选填的资料标题，最多 120 字。标题与介绍分别保存；上传失败保留输入，成功后清空。不填时兼容旧的文件名标题行为。
3. **小众对象可以独立建资源**：关联选择器可搜索全部已发布资源并继续加载匹配结果。找不到合适对象时，管理员可以从有效的已通过投稿新建并关联文化资料或文化地点，必须明确确认名称、类型与地区。普通投稿、通过审核或 AI 候选都不会自动创建资源。

新增控件沿用当前纸本颜色、字体、分隔线及折叠操作区，不改变五栏目导航或已有页面动效。

## 数据与安全

- 新增管理员动作 `withdrawSubmission`、`createResourceFromSubmission`、`searchSubmissionResources`，全部位于现有管理员鉴权后。
- 撤回使用独立的 `withdrawn` 状态，原 `pending` 审核前置条件保留。事务保存撤回状态和审计；重复请求不重复记账，后续依赖标记失败可从已撤回页重试。
- 依赖来源的证据、任务、候选、故事、图谱、专题、讲解及征集进入停止或待复核状态。公开读取再次核对来源，包括任务自身来源及智能体曾生成的实体/关系来源，避免部分传播失败时仍显示。
- 完整故事保存前核对模型读取过的全部来源，不只核对最终文稿列出的来源；正在生成时撤回也应停止保存。
- 新资源创建、绑定及日志在一个事务内完成。防止重复点击和并发重复创建；已存在但未公开的同名资源不自动恢复，不误提示用户选择不可用资源。
- 新资源只公开管理员确认的名称、类型与地区，不复制投稿说明、原文件、精确坐标或用户身份。即使选择文化地点，地图与路线能力也默认关闭。
- 公开统计与积分规则不新增奖励、不自动追回已有奖励；未增加模型、OCR 或语音调用。
