### 瓦片预加载评估（尚未实施）

现状：地图在 DOMContentLoaded 即初始化，并非每次切页重建。但隐藏地图容器不足以预热完整首屏；Leaflet 默认 keepBuffer=2 是保留已加载的周围瓦片，不会主动下载整个外圈。瓦片淡入本身已有引擎支持。

建议：首屏内容完成后按网络情况有限预热“预计进入地图时的一个视口、当前层级”；访问后保留地图实例、利用正常 HTTP 缓存，必要时仅预取近邻。慢网/省流量时关闭，限并发与总张数，不占用首页关键资源。先核对当前高德瓦片接入方式的使用与缓存许可，再确定主动预取方案；不直接批量抓取或永久保存瓦片。

内存估算：现有瓦片实际尺寸 256×256，按 RGBA 每张像素 256×256×4=0.25 MiB；本次 DOM 15 张已加载瓦片约 3.75 MiB。预热 20/40/80 张对应约 5/10/20 MiB 解码像素；这是计算估算，不是浏览器进程或显存实测。还存在 DOM、缓存、旧层级过渡、GPU 纹理及其他页面内存，压缩下载流量也不是此数值。

同一地理范围放大一级瓦片数量约四倍，多两级约十六倍；因此不预热所有比例。缩放时可先临时缩放旧图，目标层级按需加载并淡入，暂时较软，清晰后替换。不能保证未访问区域或任意缩放离线/瞬开。

技术依据：[Leaflet GridLayer 参数与事件](https://leafletjs.com/reference.html#gridlayer)（tileSize、keepBuffer、updateWhenIdle、updateWhenZooming、tileload/load）。高德缓存许可未核实，不把 JSAPI 脚本加载条款误当成当前瓦片的离线许可。
