# 楚韵链迹开发计划复核

更新日期：2026-08-16

本清单由仓库文档、现有代码入口和 Git 提交记录交叉核对得出。它用于区分“已经有真实云端闭环”“只做了一部分”和“仍未开始”，避免后续重复开发或把演示数据当成正式功能。

## 已完成，不应重复建设

- CloudBase 正式投稿、云存储、管理员审核、积分发放和个人上传记录；
- 普通账号注册、登录、忘记密码，以及管理员 UID 白名单；
- 评论、回复、点赞、举报、通知和后台内容管理；
- 福利兑换码、条形码展示、管理员查询与核销；
- 高德路线服务的基础驾车、步行和公交查询；
- 统一资源模型、31 条资源导入、只读资源接口；
- 确定性资源检索、可解释的同类推荐和详情内“顺着线索看”；
- 审核投稿的资源候选、管理员确认绑定、历史投稿补关联和审计日志；
- 人工链迹关系、AI 候选关系、管理员确认、带来源故事草稿和人工发布；
- 发现页投稿内短故事、故事质量门槛和新版链迹关系视图。
- 故事版本纠错与补充反馈、管理员处理、用户通知和追溯日志。

## 已完成阶段：链迹补充、材料版本与故事反馈

目标是保持用户端只有一个主要动作：

1. 用户在投稿详情点击“补充这段链迹”；
2. 直接选择当前补充位置支持的文件，不进入新的多层页面；
3. 补充资料进入现有管理员审核池；
4. 审核通过后更新投稿的材料版本和完整度；
5. 故事工作台显示“有新补充待更新”；
6. 下一次生成故事使用新材料版本，不读取旧缓存；
7. 管理员核对后发布为新故事版本，旧版本继续保留。

原来的细分补充位置继续保留，但默认折叠在“更多补充方式”中。

已发布故事现在也可以直接提交纠错或来源补充；反馈绑定具体故事版本和章节，管理员处理后向用户回复，但不会自动改写已发布内容。

## 尚未完成的高优先级计划

### 1. 统一资源驱动整个前端（兼容接管已完成）

用户端现已在启动时读取 `appCore/getResources`，并通过旧 ID 别名更新发现内容、地图点位和活动路线的公共元数据；云端不可用时自动保留原有页面数据。后续仍需把成熟长文、路线步骤等内容逐步迁入资源详情，但不再采用一次性替换方式。

### 2. 同类资源归类与检索（确定性第一阶段已完成）

云端已能使用资源类型、地区、标签、分类、关键词和已确认链迹进行稳定排序，发现详情会显示理由明确的相关资源，原搜索框也已纳入云端标签和分类。尚未完成跨用户投稿的资源绑定、同义词表和向量相似度；这些应在内容审核与多模态提取稳定后继续。

### 3. 多模态 AI 材料处理

当前 AI 只读取经过脱敏的文字元数据。图片 OCR、图像内容识别、音频转写和视频抽帧尚未实现，不能声称模型已经看过用户文件。接入时仍需用户单独授权，并把结果作为候选分析交给管理员确认。

### 4. 个性化游览与讲解

高德路径查询已接通，但根据位置、时间、兴趣自动排序点位，生成简短讲解、语音稿和途中提示仍未完成。应在多点路线稳定后再接 AI，地图道路结果继续以高德为准。

### 5. 微信小程序

当前正式产品仍是网页。微信登录、小程序页面、隐私授权、上传组件、地图组件和审核发布流程尚未适配；不能把现有网页地址直接视为小程序版本。

## 后续业务型计划

- 商家独立核销账号及商家—福利授权映射；
- 与真实商家确认库存、有效期和使用规则，停用未确认福利；
- 社区活动的云端创建、报名、名额和签到，而不是静态活动卡；
- 徽章与活动、贡献类型和真实权益之间的解锁规则。

## 后续统一分阶段路线

### 阶段 7：统一资源详情深化

1. 把已经成熟的历史长文、参观提示和路线步骤迁入 `resources`；
2. 资源详情仍以故事为主，长文、路线和链迹作为渐进展开内容；
3. 先迁移少量代表资源并验证兼容，再逐批扩大，不一次性替换旧内容。

完成条件：资源详情在手机、平板和桌面均可阅读；旧 ID 别名、地图和投稿关联不回退。

兼容式第一批已完成：

- “顺着线索看”不再把没有旧页面的资源直接判为不可打开，统一进入资源详情；
- 详情先提供“阅读共同故事”，到访采集提示和路线步骤默认折叠；
- 点位可继续进入地图，图文可返回关联投稿，路线可继续进入真实地图规划；
- 内容读取优先使用 `getResourceDetail`，云端暂不可用时回退已同步的公开资源，不写生产数据；
- 已完成 390、768、1440 三档验收。成熟长文的逐批数据迁移仍需单独预览与确认。

### 阶段 8：规则型个性化游览

1. 用户明确选择可用时间、步行强度和兴趣；
2. 使用已发布资源与高德真实道路结果进行确定性排序；
3. 解释每个推荐点位为何入选，并允许用户手动增删和调整顺序；
4. 不让 AI 编造道路、开放时间或历史事实。

完成条件：没有模型也能生成可解释的多点路线；路线失败时保留手动选择能力。

### 阶段 9：检索与归类增强

1. 建立经过人工维护的同义词表；
2. 将跨用户投稿稳定绑定到统一资源；
3. 增加错别字、别名和地区组合检索；
4. 向量相似度仅作为候选排序，不直接建立公开关系。

完成条件：常见别名能找到同一资源，候选关联仍需管理员确认。

### 阶段 10：授权后的多模态材料处理

1. 先完成用户逐类授权、撤回授权、成本和调用限额；
2. 再接 OCR、图像候选识别、音频转写和视频抽帧；
3. 识别结果写入候选分析，不能覆盖原始资料或自动发布；
4. 供应商、费用和生产开关需单独确认后启用。

完成条件：授权、审计、限额、失败重试和人工确认全部可验证。

### 阶段 11：讲解、小程序与商家侧

1. 在稳定路线和已审核故事上生成短讲解与语音稿；
2. 完成微信登录、隐私授权、上传和地图的小程序适配；
3. 最后建设商家独立核销、库存和权益规则。

完成条件：网页正式流程不回退，小程序和商家权限经过独立安全验收。
