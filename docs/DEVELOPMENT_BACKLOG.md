# 楚韵链迹开发计划复核

更新日期：2026-08-16

本清单由仓库文档、现有代码入口和 Git 提交记录交叉核对得出。它用于区分“已经有真实云端闭环”“只做了一部分”和“仍未开始”，避免后续重复开发或把演示数据当成正式功能。

## 已完成，不应重复建设

- CloudBase 正式投稿、云存储、管理员审核、积分发放和个人上传记录；
- 普通账号注册、登录、忘记密码，以及管理员 UID 白名单；
- 评论、回复、点赞、举报、通知和后台内容管理；
- 福利兑换码、条形码展示、管理员查询与核销；
- 高德路线服务的基础驾车、步行和公交查询；
- 统一资源模型、31 条资源导入、只读资源接口；
- 人工链迹关系、AI 候选关系、管理员确认、带来源故事草稿和人工发布；
- 发现页投稿内短故事、故事质量门槛和新版链迹关系视图。

## 当前阶段：链迹补充与材料版本

目标是保持用户端只有一个主要动作：

1. 用户在投稿详情点击“补充这段链迹”；
2. 直接选择当前补充位置支持的文件，不进入新的多层页面；
3. 补充资料进入现有管理员审核池；
4. 审核通过后更新投稿的材料版本和完整度；
5. 故事工作台显示“有新补充待更新”；
6. 下一次生成故事使用新材料版本，不读取旧缓存；
7. 管理员核对后发布为新故事版本，旧版本继续保留。

原来的细分补充位置继续保留，但默认折叠在“更多补充方式”中。

## 尚未完成的高优先级计划

### 1. 统一资源驱动整个前端（兼容接管已完成）

用户端现已在启动时读取 `appCore/getResources`，并通过旧 ID 别名更新发现内容、地图点位和活动路线的公共元数据；云端不可用时自动保留原有页面数据。后续仍需把成熟长文、路线步骤等内容逐步迁入资源详情，但不再采用一次性替换方式。

### 2. 同类资源归类与检索

目前只有标签和静态搜索，没有真正的云端分类索引、相似资源推荐或跨投稿检索。应先使用资源类型、地区、标签和已确认链迹做确定性检索，再考虑向量相似度。

### 3. 多模态 AI 材料处理

当前 AI 只读取经过脱敏的文字元数据。图片 OCR、图像内容识别、音频转写和视频抽帧尚未实现，不能声称模型已经看过用户文件。接入时仍需用户单独授权，并把结果作为候选分析交给管理员确认。

### 4. 个性化游览与讲解

高德路径查询已接通，但根据位置、时间、兴趣自动排序点位，生成简短讲解、语音稿和途中提示仍未完成。应在多点路线稳定后再接 AI，地图道路结果继续以高德为准。

### 5. 微信小程序

当前正式产品仍是网页。微信登录、小程序页面、隐私授权、上传组件、地图组件和审核发布流程尚未适配；不能把现有网页地址直接视为小程序版本。

## 后续业务型计划

- 商家独立核销账号及商家—福利授权映射；
- 与真实商家确认库存、有效期和使用规则，停用未确认福利；
- 社区活动的云端创建、报名、名额和签到，而不是静态活动卡；
- 用户对故事提出纠错/补充意见，并形成可追溯的编辑反馈；
- 徽章与活动、贡献类型和真实权益之间的解锁规则。

## 推荐顺序

1. 完成同类资源检索；
2. 接入 OCR/转写等多模态分析；
3. 完成个性化路线与语音讲解；
4. 继续把长文和路线步骤迁入统一资源详情；
5. 最后进行微信小程序适配和商家侧建设。
