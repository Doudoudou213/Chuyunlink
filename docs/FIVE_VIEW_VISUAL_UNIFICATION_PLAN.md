# 楚韵链迹五页面视觉统一规划（本轮发现页冻结）

更新日期：2026-08-24  
适用分支：`ui/visual-redesign`  
当前阶段：方案评审，不实施页面改动、不提交、不部署  

## 1. 目标与范围

长期目标仍是让五个主导航页面形成同一套视觉语言，但本轮以已经完成的“我的”页为基线，只改造“活动科普、地图、采集、我的”四页，**发现页暂时冻结，不做任何视觉或结构调整**：

1. 发现：`#view-discover`（冻结，只做回归对照）
2. 地图：`#view-map`
3. 采集：`#view-collect`
4. 活动科普：`#view-community`
5. 我的：`#view-profile`

本轮统一不等于把四个目标页面做成同一张模板。它们应共享宣纸底色、字体层级、按钮语义、状态色、投影和间距，同时保留清楚的产品角色。发现页继续保持当前状态，待以后单独评审和授权：

- 发现页是“内容展陈”，本轮不动；
- 地图页是“实地寻访”；
- 采集页是“田野手记”；
- 活动科普页是“活动册与学习册”；
- 我的页是“个人图鉴展厅”。

### 严格边界

- 保留全部既有 DOM id，特别是 `view-community`、`community-route-card`、`quiz-question`、`quick-learning-list` 等。
- 保留既有事件入口和函数签名，包括活动报名、路线、地图、讨论、答题、速学与 CloudBase 交互。
- 不改变数据库结构、积分规则、活动数据、审核逻辑、路由逻辑和 CloudBase 云函数。
- 当前活动封面图片先保持不变，只调整遮罩、裁切焦点和文字排布；更换素材必须另行确认来源与授权。
- 不修改 `#view-discover` 内的结构、类名、卡片、筛选、图片、文案、间距或状态样式。
- 本轮不重构全局页头与底部导航，避免共享选择器间接改变发现页；若必须修复跨页问题，需先证明发现页截图无视觉变化。
- 只在 `ui/visual-redesign` 分支工作，不合并到 `shan`。
- 每一阶段先提供效果图，获得确认后再进入下一阶段；部署仍需单独授权。

## 2. 对原指南的理解

原指南确立了正确的总体方向：

- 以宣纸米白为全局托底，消除活动页残留的纯白和冷灰；
- 以夜漆、漆器棕、鎏金、楚朱红和楚石绿建立文化语义；
- 卡片去除冷灰描边，改为暖色实体表面与轻微弥散投影；
- Banner 用暗色渐变保证标题、标签与操作的可读性；
- 路线、答题和速学三个模块分别建立明确的状态反馈；
- 只改表现层，不破坏原有业务交互。

这套方向可以作为活动科普页的设计输入，但不应直接把示例代码逐字复制进项目。当前项目已有视觉 token、响应式规则、动态渲染函数和“我的”页组件，需要先做统一和兼容。

## 3. 当前代码基线与风险

### 3.1 已经具备的基础

- 全局已有宣纸色、漆器色、暖色投影与页面水印。
- “我的”页已形成低密度、缩略图主导、图鉴展厅式的可用基线。
- 发现、地图、采集、活动科普已经有一轮局部暖色覆盖。
- 底部五项导航已实现桌面与移动端响应式布局。
- 答题、路线卡和速学卡均有真实交互，不是纯静态展示。

### 3.2 必须先解决的问题

1. **存在两套颜色 token。** 当前同时存在“夜漆朱凤”变量和另一套 `paper/camel/raspberry` 变量，同一个颜色语义可能由不同十六进制值承担，后续继续硬编码会扩大偏差。
2. **CSS 覆盖层较多。** 原 Tailwind 类、后加的全局 CSS 与“我的”页专属 CSS 叠加，部分样式依赖 `!important`，容易出现初始状态正确、交互后恢复旧样式的问题。
3. **活动内容包含动态 HTML。** 路线卡由 `renderCommunityRouteCard()` 生成，路线周边由 `renderRouteServicePanel()` 生成，速学卡由 `renderQuickLearning()` 生成，答题结果也会运行时重写 `className`。只改静态 HTML 不足以完成重构。
4. **当前指南的触控尺寸不足。** 示例中的 `py-1.5` 和现有 40px Banner 按钮不满足项目约定的最小 44px 触控区。
5. **移动端信息仍偏密。** 三个 Banner 操作并排、路线三步并排、周边服务双列、速学双列叠在同一屏，会再次接近通用小程序或 SaaS 卡片墙。
6. **字体类不应混用。** 指南中的通用 `font-serif` 不保证使用项目已加载的中文宋体，应统一到明确的中文展示字体类。
7. **语义色不能只靠类名模糊覆盖。** 目前对所有 `emerald` 类进行全局替换，会把“成功”“已完成”“已核实”等不同状态压成同一种金色，削弱信息含义。

## 4. 对指南的改进建议

### 4.1 先统一语义 token，再改模块

不再在各模块散落 `#fffaf1`、`#241a17`、`#9e2f24` 等硬编码值，统一使用语义变量。建议核心色如下：

| 语义 | 建议值 | 用途 |
| --- | --- | --- |
| 宣纸底 `--chu-paper` | `#F5EFE4` | 本轮四个目标页面背景；发现页沿用现状 |
| 骨白面 `--chu-surface` | `#FBF7EF` | 卡片、抽屉、悬浮面板 |
| 暖杏层 `--chu-surface-warm` | `#EEE3D2` | 次级内容、输入区、路线步骤 |
| 玫瑰墨 `--chu-ink` | `#4B2E2B` | 主文字与图标 |
| 暗驼棕 `--chu-action` | `#592620` | 主要操作与当前导航 |
| 鎏金 `--chu-gold` | `#B68A4A` | 等级、强调、装饰性小面积信息 |

辅助状态色：

- 夜漆黑 `#17110F`：只用于图片遮罩和极少量沉浸区域，不做大面积普通卡片。
- 楚朱红 `#9E2F24` / 覆盆子红 `#AC1F18`：用于印章、错误、进行中和关键提醒，避免铺满整块界面。
- 楚石绿 `#496A61`：只用于完成、已核实、已入藏等小范围正向状态。
- 石榴籽粉 `#F1908C`：只用作聚焦微光或红色的浅层反馈，不作为正文色。

“暖杏色卡片”不应使用几乎纯白的 `#FFFAF1` 来命名；建议把 `#FBF7EF` 定义为骨白面，把 `#EEE3D2` 定义为真正可见的暖杏层，从而形成稳定层级。

### 4.2 统一表面、圆角与投影，而不是所有元素都卡片化

建议建立三档表面：

- 页面底：无边框、无阴影；
- 普通内容面：12px 圆角，`0 8px 24px rgba(65,39,27,0.06)`；
- 沉浸主视觉：16px 左右圆角，`0 12px 32px rgba(65,39,27,0.12)`。

标签使用 4–6px 小圆角，避免所有控件都变成胶囊。列表项和次要动作尽量平铺，用间距、底色变化和文字层级区分，不再为每一项增加描边矩形。

### 4.3 调整按钮层级，降低移动端拥挤

原指南的三个 Banner 按钮都做成圆角块，在窄屏上密度过高，也与此前“按钮平铺”的偏好不一致。建议改为：

- “报名活动”是唯一实心主按钮，触控高度不低于 44px；
- “看任务点”和“讨论”改为同一行的图标文字次操作，保留 44px 触控区，但不各自形成厚重卡片；
- 路线底部仍保留三个功能，但移动端使用“一个主操作 + 两个次操作”，平板及桌面再恢复三列；
- 所有 `hover` 必须同时有 `focus-visible`，按下反馈不依赖动画，且尊重 `prefers-reduced-motion`。

### 4.4 提高正文可读性

- 10px 只用于非关键时间戳或辅助编号；标签建议至少 11–12px，正文至少 13–14px。
- 页面标题和模块标题明确使用 `Noto Serif SC`；正文、按钮和状态使用 `Noto Sans SC`。
- 重要状态不能只靠红/绿颜色表达，应同时保留文字、图标或形状差异。
- 遮罩后的 Banner 文本需以实际截图检测对比度，不能只以“加了 90% 渐变”推断 100% 可读。

### 4.5 使用楚文化内容，而不是泛国风装饰

四个目标页面共同的标志性元素建议是“朱漆链迹”：一条克制的细线在路线步骤、采集进度和个人图鉴状态中承担真实的信息连接作用。发现页本轮不新增或调整该元素。

水印只作为低频辅助：每页最多一个，透明度保持约 4%–6%，并使用凤鸟纹、楚简、编钟节律或漆器曲线。避免宫墙、祥云、印章同时堆叠，防止回到泛国风模板。

图片继续优先真实荆楚文化素材。任何新图片必须记录来源、授权和替代文本；本阶段不擅自替换活动封面。

## 5. 活动科普页修订方案

### 模块 A：活动领衔 Banner

保留原指南的沉浸图片和底部暗色渐变，但做以下调整：

- 使用语义 CSS 类实现遮罩、表面和按钮，不在 HTML 中继续堆叠任意值类。
- 保留“进行中”朱红印章；“已报名”使用低对比骨白玻璃标签，二者不争夺层级。
- 标题使用中文展示字体，描述在移动端最多两行，而不是强制一行造成信息损失。
- 主按钮与两个次操作分层布局，确保 390px 宽度下不挤压、不换成超小字号。
- 为图片定义移动端与桌面端焦点位置，并保留清晰的 `alt`。
- 现有竖排“楚纹寻访”只在不遮挡图片主体时保留，窄屏可隐藏。

### 模块 B：今日推荐路线

原指南只覆盖主路线卡，但当前实现还包含“路线周边”与外部服务入口，因此需要完整纳入：

- 卡片使用骨白面，步骤区域使用暖杏层，不保留冷灰边框。
- 城市、路线属性、距离、时长分别使用金、绿和中性语义，避免四个标签同时高亮。
- 移动端步骤改为横向链迹或纵向列表，不再用三块窄卡硬挤；平板以上可以三列。
- 步骤数字必须真的是路线顺序，使用朱漆链迹连接，装饰与信息含义一致。
- “路线周边”降为可展开的次级内容，默认不与主路线争夺首屏空间，但原功能完整保留。
- 外部平台入口采用文字链接或轻量按钮，明确即将离开本站。

### 模块 C：三分钟科普闯关

- 面板使用骨白面，问题区不额外套卡。
- 选项使用暖杏纯色块、透明边框和 44px 以上触控高度。
- 聚焦状态使用鎏金外轮廓；选择后同时用图标、文字与颜色反馈。
- 正确状态使用楚石绿，错误状态使用楚朱红；解析框用淡金底，但不能把错误解析也统一覆盖成金色。
- 需要同步修改初始化和答题结果的运行时 class，避免答题后跳回 `emerald/red/stone` 旧样式。
- 已作答、未作答、正确、错误、跨日重置和本地状态恢复都要纳入验收。

### 模块 D：采集前速学

原指南的“双列 SaaS 卡片”问题不能只靠换底色解决。建议：

- 手机端采用单列编辑型知识条目，左侧为楚文化线稿或小型主题图，右侧为标题、时长和状态；平板以上再用双列。
- 图标不使用深色方块底，统一为可编辑 SVG/Lucide 线稿；如需新增楚文化图标，沿用现有代码化图标系统。
- “已学会”使用楚石绿文字角标并附带勾选图标；积分属于次要信息，不与标题抢层级。
- “换一组”改为平铺的图标文字操作，保持 44px 触控区。
- 加载、空内容、已完成和刷新失败状态都使用同一套纸面语言。

## 6. 四页面改造规则与发现页冻结规则

| 页面 | 保留的专属气质 | 需要统一的内容 | 需要避免 |
| --- | --- | --- | --- |
| 发现 | 图片主导的数字展陈、故事优先 | 本轮不改，只保存截图并做回归对照 | 任何结构、样式、文案或共享 CSS 的间接变化 |
| 地图 | 地图画布、真实点位与路线 | 抽屉、规划器、弹窗、标记语义、按钮层级 | 把地图也铺成米白；控制层冷白割裂 |
| 采集 | 楚简式田野手记、分段表单 | 输入面、上传区、主操作、校验状态 | 每个字段单独描边卡片、后台表单感 |
| 活动科普 | 活动册主图、朱漆路线、知识学习 | Banner、路线、答题、速学、状态反馈 | 三列挤压、通用卡片宫格、过小文字 |
| 我的 | 图鉴展厅、投稿缩略图 | 导航、标题、状态 token、空态与其他页一致 | 恢复深色账户大卡、七宫格功能入口 |

### 共用组件清单

- `chu-page-shell`：宣纸底、页面宽度与安全区；
- `chu-section-header`：中文标题、可选英文题签与次操作；
- `chu-surface` / `chu-surface-warm`：普通面与暖杏层；
- `chu-action-primary` / `chu-action-secondary` / `chu-action-quiet`：三级操作；
- `chu-status-*`：进行中、已完成、待处理、错误等状态；
- `chu-focus-ring`：统一键盘聚焦；
- `chu-empty-state`：空内容、失败与恢复指引；
- `chu-trace-line`：有真实顺序或关系时才使用的朱漆链迹。

### 阶段 0：现状冻结与交互清单

1. 保存五页在 390、768、1440 三档宽度的当前截图。
2. 记录活动页所有静态 id、内联事件、动态渲染入口和状态切换。

4. 把发现页截图设为不可变化的回归基线。
5. 不修改业务代码，不部署。

交付物：五页基线截图、交互契约清单、样式冲突清单。

### 阶段 1：视觉系统样稿

1. 先制作活动科普页移动端效果图，同时给出关键桌面布局。
2. 效果图必须覆盖 Banner、路线展开前后、答题正确/错误、速学完成状态。

4. 用户确认后才进入真实代码。

交付物：效果图与 token 表；这一阶段不接触 CloudBase。

### 阶段 2：建立四页面共享基础

1. 为四个目标页建立语义 token 映射；本轮不删除或重定义发现页正在使用的变量。
2. 所有新规则明确限定在 `#view-map`、`#view-collect`、`#view-community` 与 `#view-profile`，不使用会命中发现页的宽泛选择器。
3. 本轮保持全局页头、底部导航以及发现页现有 token 表现不变。
4. 在四个目标页内统一页面底、焦点样式、投影和圆角尺度。
5. 保留地图画布本身，只统一地图上的纸面控制层。
6. 先做独立提交，形成可撤销点。

交付物：仅基础视觉系统的提交与三档截图。

### 阶段 3：活动科普页实施

1. 按确认稿重构 Banner。
2. 同步重构静态 HTML 与动态路线、周边服务、答题结果、速学渲染模板。
3. 保留全部 id、事件函数和数据逻辑。
4. 覆盖所有交互状态并进行三档视口验收。
5. 单独提交，便于精确撤销。

交付物：活动科普页提交、前后对照图、交互验收记录。

### 阶段 4：其余三页统一

按风险从低到高进行：

1. “我的”页只校准四页共享 token，不重做已确认结构，也不改全局导航。
2. 采集页统一输入、上传、校验和提交动作，保留楚简分段特征。
3. 地图页统一浮层、弹窗与标记色，地图内容和路径逻辑不动。

发现页不进入本阶段；它只作为回归基线。后续若要调整，另做效果图、另行确认、另建提交。

每一页独立截图、独立验收；建议每页或每一类共享组件单独提交。

### 阶段 5：全局设计 QA

1. 四个目标页在 390、768、1440 宽度下逐页截图并并排检查。
2. 核对四个目标页的页面背景、字体、状态色、圆角、投影和间距是否一致。
3. 检查横向溢出、长标题、无图片、空列表、加载、错误、登录与未登录状态。
4. 检查所有主要交互最小 44px、键盘焦点、颜色对比、语义标签和减少动画偏好。
5. 运行前端语法与仓库构建校验，确认无控制台异常。
6. 重新截取发现页并与阶段 0 基线比较，确认没有被共享样式间接改变。
7. 形成 `design-qa.md` 更新记录；确认通过后才申请提交、推送与部署授权。

## 8. 技术实施原则

- 优先使用语义 CSS 类和 token，不再依赖大量针对旧 Tailwind 类的属性选择器覆盖。
- 不以“全局替换所有 `emerald` / `stone`”的方式改状态色；按业务状态明确映射。
- 静态 HTML 和运行时生成的模板必须同步修改。
- 不为了视觉重构迁移函数、改名 id 或重写业务流程。
- 所有动态文本继续经过现有转义函数，视觉代码不得绕开安全处理。
- 如新增素材，必须使用本地可控资源或明确授权来源，并保留来源说明。
