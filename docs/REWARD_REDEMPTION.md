# 反哺专区真实兑换码

## 已实现的云端链路

- `appCore/bootstrap` 返回云端福利、真实积分和当前用户的兑换记录。
- `appCore/redeemReward` 只接受 `rewardId` 和幂等请求编号，价格、库存和限购均以云端为准。
- 数据库事务同时扣积分、扣库存、更新限购、生成兑换凭证并写入积分流水。
- 兑换码使用服务端密码学随机数生成，格式为 `CHU-XXXX-XXXX-XXXX`。
- 浏览器不能自行修改积分价格、库存、兑换码或兑换状态。

## 必须设置的数据库权限

在 CloudBase 控制台的“文档型数据库 → 集合管理 → 权限管理”中，将下列集合切换为安全规则：

- `rewards`
- `reward_redemptions`
- `reward_redemption_counters`
- `point_ledger`
- `reward_redemption_logs`

上述敏感集合统一使用：

```json
{
  "read": false,
  "write": false
}
```

前端只通过云函数取得已脱敏的福利和本人兑换凭证，不需要数据库客户端直读权限。

## 核销工作台

- 现阶段只有 `ADMIN_UIDS` 中的管理员可以进入 `admin.html` 核销。
- 核销员必须先查询兑换码，核对福利、状态、有效期和使用说明。
- 核销事务重新读取最新状态，只有 `issued` 可更新为 `redeemed`，重复或过期凭证会被拒绝。
- 成功核销会写入 `reward_redemption_logs`，同时向用户发送核销通知。
- 后续如果向商家开放独立账号，需要增加商家与 `rewardId` 的授权映射，不能直接把所有核销权限开放给普通账号。

## 上线前业务确认

系统生成的是“楚链平台兑换凭证”。商家需要事先确认福利名称、库存、使用规则和有效期，并使用后续的商家核销页核销。未经商家确认的福利应设置为 `inactive`。
