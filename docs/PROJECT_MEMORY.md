## 1. 产品定位

“楚韵链迹”是面向荆楚物质文化遗产的众包采集、审核、关联和讲述平台。

用户上传照片、文字、音频、视频与地点资料；管理员完成审核；系统将不同时间、地点和用户的投稿关联到统一文化资源，形成有出处、可修订、可继续补充的“链迹”，再以简短故事、地图、时间线和后续讲解方式呈现。

核心价值不是生成一段 AI 文案，而是：

1. 保留原始文化证据；
2. 让每项公开结论可追溯到审核资料；
3. 允许公众持续补充；
4. 让 AI 只做识别、候选关联和草拟，最终事实与发布由人确认。

## 3. 技术结构

### 前端

- `index.html`：用户端单页应用，当前主 UI 编辑源。
- `static/cloudbase-app.js`：CloudBase 前端适配、数据加载和交互覆盖层。
- `admin.html`：管理员后台。
- Tailwind CDN、Lucide、Leaflet、CloudBase Web SDK。
- `pages/` 中的 uni-app x 示例不是当前正式产品；当前正式产品仍是网页。

### 云端

- `appCore`：用户端核心读写与公开数据接口。
- `adminSubmissions`：管理员审核、链迹、故事与业务管理。
- `storyWorker`：AI 候选关联和带来源故事任务。
- `materialWorker`：图片 OCR 等多模态材料任务。
- CloudBase 数据库、云存储与静态网站托管。

### 关键数据层

- `submissions`：原始投稿，AI 不得覆盖。
- `resources`：统一文化资源。
- `story_evidence_links`：审核确认的投稿—资源证据关系。
- `story_chains`：带来源、可版本化的故事结构。
- `ai_link_candidates`：AI 关联候选，不能直接公开。
- `material_analysis_jobs / material_analyses / material_analysis_logs`：材料识别任务、结果与审计。

## 5. 当前多模态状态

当前图片 OCR 代码已经存在，但真实识别默认关闭。

- 安全模拟：`material-image-mock-v1`。
- 真实适配器：腾讯云 `GeneralBasicOCR`。
- 默认要求：`MATERIAL_MODE=mock_only`、`MATERIAL_REAL_OCR_ENABLED=false`。
- 真实 OCR 只有在专用 CAM 子用户凭证与开关同时配置后才可运行。
- 单图上限 5 MB；每日默认 20 次；短时文件地址；敏感字段落库前脱敏。
- 结果必须经管理员校对后才可标记为故事可用材料。
- `storyWorker` 当前尚未读取 `material_analyses`，不要误称 OCR 已进入正式故事生成。

密钥只能放在 CloudBase 云函数环境变量，不能写进 GitHub、`cloudbaserc.json`、前端或聊天。

## 6. 长期产品与安全决策

- 低质量或证据不足时不生成故事，只提示缺少什么资料。
- 故事面向投稿卡片：短标题、短导语、最多两段正文；避免“穿越千年”“文化瑰宝”等空泛套话。
- 关键内容必须绑定真实来源；故事草稿不能自动发布。
- 用户旧投稿缺少授权字段时视为未授权，不补写授权。
- 公开接口不返回用户 UID、私有 fileID、管理员 UID 或内部审核字段。
- 新关系和故事集合禁止客户端直接读写，统一通过云函数脱敏。
- 原始投稿不物理删除；关系与故事使用状态、日志和版本记录实现追溯。
- AI 不负责权限、积分、审核、兑换、核销或历史事实裁决。

## 7. 已确认的前端改进方向

当前 UI 参考来自三组国风文化类移动端界面。需要继承的优点：真实文化素材主导、博物馆式留白、低饱和器物色、沉浸大图、清晰探索入口，以及内容—地图—活动—服务的完整结构。

不能直接照搬“米白底 + 宫墙红 + 古建图标”的泛国风模板。楚韵链迹采用更具体的 **“夜漆朱凤”** 方向：

- 主色：夜漆黑 `#17110F`、楚朱红 `#9E2F24`、骨白 `#F3EBDD`、青铜锈 `#496A61`、鎏金 `#B68A4A`、墨褐 `#2B2421`。
- 色彩语义：夜漆黑、楚朱红和鎏金承担品牌与主要操作；青铜锈只用于“已核实、在线、成功”等小范围状态，不作为大面积主背景，避免红绿同时争夺视觉层级。
- 文化母题：楚漆器曲线、凤鸟纹、编钟节律、楚简竖向结构、虎座鸟架鼓。
- 标志性交互：一条“朱漆链迹”串联发现地点、年代、纹样、人物/事件、修复与数字凭证。
- 卡片圆角克制，减少通用小程序式均匀宫格；内容页采用数字展柜与卷轴式阅读面板。
- 底部主导航建议为：探楚、链迹、藏品、我的。
- 优先落地：首页与链迹详情；之后再扩展地图、搜索、藏品和个人中心。
- 首页故事默认直接位于投稿下方；链迹图是可选展开内容。链迹详情默认先读“故事讲述”，其次查看来源记录，最后按需打开链迹图。

视觉实现应使用 `$frontend-design` 做方向校准，Figma 建立变量/组件，ImageGen 只生成原创位图素材；导航图标、Logo 和组件应保持 SVG/代码可编辑。

## 8. 后续优先级

近期：

1. 先完成用户端首页与链迹详情的视觉重构，不破坏现有业务闭环。
2. 让管理员确认的真实 OCR 材料进入 `storyWorker`，但继续保持人工发布。
3. 继续把成熟长文和路线步骤迁入统一资源详情。
4. 建立同义词表、跨投稿资源绑定和更稳定检索。

中期：

1. 音频转写、视频抽帧与材料人工校对。
2. 个性化路线、简短讲解、语音稿和途中提示。
3. 用户故事纠错与补充反馈。

后期：

1. 微信小程序适配；当前网页不能直接视为小程序版本。
2. 商家独立核销账号与福利授权映射。
3. 活动创建、报名、名额和签到云端闭环。

- 重要改动应小步提交，前后执行相关测试并做移动端、平板、桌面截图检查。
