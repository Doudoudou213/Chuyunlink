### 视觉方向：一幅画、一张笺、一个重点

- **延续已认可的主题**：黄鹤楼保留暗色山水与暖黄旧纸；全站通用页保留宣纸米白。学习用户提供的茶颜/茶姬参考中“大图有主角、文字有层次、插画与背景相连”的方法，不搬用商标或商业插画。
- **主画面**：让原画承担首屏主体，景点名只作题签；不另做厚重标题栏，不用大口号压景。图边延续柔化，但不模糊景物本身和可点击位置。选中点位沿用原画内的金光，不叠重复景物贴图。
- **旧纸不是脏纸**：褶皱、纤维和投影集中在纸边、页角与空白；正文区更平整。水印仍在，但避开主要文字，四景按各自原画取景，不每页重复同一块重纹理。
- **字体分工**：手写体只给景名或短题签；宋体用于故事；系统无衬线用于按钮、状态、数字。正文不使用书法字，不用淡色细字制造高级感，不加装饰性英文和无意义编号。
- **布局不是卡片墙**：看景是画面，读景是一张纸；不把每段正文、每个按钮再套小卡片。功能分组靠间距和位置，不靠一圈圈描边。
- **唯一标志性动作**：从画中取出一页笺，读完后纸页让位给下一景。其他控件安静，避免漂浮、扫光、粒子、翻页同时争抢注意力。

### 文字减量的具体办法

1. **看景层**：景名、一个观察问题、一个主操作。不是零文字，也不是图上堆满说明。未审/非实景等边界用明确短句常驻，详细解释收纳。
2. **读景层**：首先回答一个问题，之后再给依据与有兴趣的补充。短摘与完整内容之间不做多层弹窗，不能为了减字把重要限定条件截掉。
3. **查证与工具层**：出处、大字、帮助、版本详情按需出现；关键失效原因和下一步仍直接可见。出处不是隐藏到找不到，正文附近应一键可达。
4. **非游客层**：假数据库、指纹、测试脚本、发布准备、文件统计等留在工作册或维护页，不能充当游客内容；试用声明也不能因此伪装成已上线正式产品。
5. **材料安全**：改写研究稿摘要必须保留来源映射、人工审核和版本标记。现有问景引用依赖段落/来源索引，不能直接截断字符串或改段落后沿用旧映射；重新检查引用再发布，不让AI自动断言历史事实。

### 全站五栏后续如何统一（当前不实施）

- 发现：一幅主题插画引入，图片与短故事成组；投稿卡减少字段，不减少真实内容与来源入口。
- 地图：地图为主，选中点位只有一个主要阅读层；避免同时弹出多个说明面板，路线依据仍用真实服务。
- 采集：一次只要求一个关键步骤，说明在对应输入旁按需出现；授权、上传失败和提交状态不能装饰性淡化。
- 活动科普：先看到活动与一个参与动作；路线、闯关和速学分组，不同时争抢首页主视觉。
- 我的：作品和徽章优先，资料简明；系统管理功能收纳，不恢复大面积深色统计框和后台式字段。

共享的是字体角色、阅读节奏、图标/插画规则、按钮层级、纸纹材质和状态语义；不是所有页面共用一张图、同样的深底或相同首屏高度。管理员端以任务效率为先，不复制游客的沉浸画卷。

### 3. 用户旅程与界面约束

1. 进入：必要底图和控件先可用，装饰细节随后显现。动画不是阻塞式加载片头；不做假进度条。
2. 确认对象：定位可选，拒绝定位也能点选地图或参照照片。定位不确定时显示大致范围，不画假的精准位置。
3. 观察：点建筑→镜头靠近→景物细节展开→出现一张简短讲解卡。细节与资料对象有明确对应。
4. 追问：一个轻量输入入口，按需展开；可问“这是什么”“为什么这样设计”。后续照片识别先给候选，再由用户确认。
5. 查证：来源、历史图片、相关故事和贡献者在卡片内渐进展开，关闭后保留地图位置和缩放。
6. 继续或结束：用户确认到访后留印记；跳过不能算到访；结束后形成私人小手册，可按观察点补充投稿。

常驻结构只有地图、当前讲解卡和一个提问入口。记录、设置、来源、完整列表折叠展示。首屏不铺一排功能按钮。语音由用户启动，不自动播放。

### 5. 数据与代码分离约定

以下为后续设计约定，尚未新增这些结构，不应误称为当前接口字段：

- 地图配置：景区资源ID、地图版本、底图素材、示意/地理坐标类型、必要参照点、分层对象、可通行连接及各自核实时间。美术摆放坐标与地理坐标分别保存；没有标定依据不叠加精准定位。
- 观察对象：稳定对象ID、所属资源与地图版本、可核实的位置、参照图片、图片中的标注区域、讲解版本及来源引用。现有 point.id 可复用，地图修图不重建用户到访身份。
- 动效配置：对象ID、被允许的聚焦/描边/展开类型、时序、层级、静态替代画面。只改变呈现，不改变路线、授权、公开状态或用户记录。
- 音频配置：讲解版本、音频资产与权限、字幕时间标记、可高亮的对象ID。文稿换版后旧音频不能冒充新稿。
- 导览包：组合上述版本与已发布引用，保存素材清单、大小、校验指纹和授权信息。它不把私有原图/音频打包公开，也不能绕过服务端当前来源检查。

前端建议独立拆分地图数据适配、地图绘制、动效、景物细节、讲解卡和输入交互，沿用已分离的会话/来源/问答接口。具体文件名在阶段A实施时确定；原 index.html/guide.html 不承载新编辑器和动效逻辑。视觉会话可以替换画面和时序，无须修改审核或私人记录规则。

后端继续复用 resources、site_walks、site_walk_versions、site_walk_logs、guide_fragment_versions、story_claims、证据、visit_sessions 和 submissions。只有现有结构确实无法表达的地图/资产配置才增量扩展，不另造审核、贡献、通知、积分或评测系统。

### 6. 智能体与动画怎样配合

- 先确定用户选择/确认的对象，再检索该对象当前有效、可公开且满足AI授权的材料；调用前后均核对。
- 回答可以依据已确认资料即时改写，不自动升级为历史事实、正式故事或通过审核的路线。
- 模型只能建议已存在对象的有限操作，例如“高亮对象A的标注2”。服务器校验对象、来源和当前页面范围后再映射到前端动效。
- 禁止执行模型生成的脚本、任意素材地址、任意坐标或未经核实的行走指令。不存在的对象、无来源的细节和不确定识别返回说明或候选确认。
- 识别“照片里是什么”与知道“用户站在哪里、面朝哪里”分别处理。照片标注只指向照片区域，不能直接变成“请向右走”。
- 先做点选＋文字问答，再做单张照片辅助；连续摄像头、AR贴合与室内精确定位属于远期扩展，不混入A～C阶段。

### 7. 动画验收标准（本地交互已检查，实机性能目标仍待测）

| 检查项 | 目标与验收方式 |
| --- | --- |
| 视觉连续性 | 全图→对象→细节→材料→回图保持同一对象，不出现重复元素、突跳或错误层级；重点录制实际手机操作视频 |

| 加载 | 必要地图和操作先出现，装饰分层加载；首屏压缩素材暂以不超过2MiB为预算目标，阶段A记录实际体积与网络条件；不以假进度或固定等待伪装加载 |

| 降级与耗电 | 素材失效可看已有文字/对象列表；切后台停止装饰循环；低性能时减少粒子、景深和层数；页面不依赖动画才能点击 |
| 现场真实性 | 路径描绘只采用有效核实路段；模拟镜头移动不代表人在移动；印记仅由明确到访操作产生 |

### 8. 隐私、来源与失败恢复

- 不持续采集精确行踪，不默认把坐标、完整游览历史、私人照片发给模型。照片用途、上传范围、保留期限需显式说明并允许撤回。
- 来源撤回、内容下架、署名或素材权限变化后，后续读取按当前规则处理；动画和缓存都不能恢复已失效内容。当前已有轮询/操作前复核不是实时推送。
- 断网可以保留已加载的合法基础示意与私人进度；不能核对的受控正文、节选、媒体和通行方向停止新展示。没有即时撤回能力的离线包不得宣传为同步有效。
- 实地封闭或方向不确定时给出暂停/查看现场标识提示，模型不自动编造绕行路线。换版保留旧记录，重新开始当前有效导览。
- 资料不足先提供已有介绍和明确缺口；不为了让动画热闹而增加未经核实的历史人物、构件、复原景象或因果关系。

## 产品目标和第一版范围

用户根据时间、兴趣、体力和起点得到可调整的行程；途中手动确认到站，阅读有来源的短讲解、观察提示和文化联系；结束后留下私有游览记录，并可提交补充材料。

第一版建议沿用现有网页和行程篮，默认同城、最多沿用现有 8 站上限；不开放实时自由聊天。游客可在本机保存，登录后可明确选择保存至个人账号以便跨设备恢复。记录默认私有；不同账号、本机游客数据隔离，不自动把游客轨迹导入账号。定位可选，支持手动起点；不持续采集轨迹，不将精确起点或行踪发送给模型。语音先交付可朗读文本及播放适配接口，真实语音服务保持关闭。

时间约束包含前往第一站、站间交通、停留和缓冲；默认在末站结束，界面明确说明，支持用户指定终点后纳入计算。必去点无法满足时报告冲突，不偷偷删去或声称可行。已明确不适合到访、停用或封闭的地点不推荐为参观站点；参观状态未知的地点明确待核实，不能以坐标代替参观许可。无可靠道路结果时保留计划，但标记可行性待核实。

## 即时体验与人工审核如何兼容

审核对象是可复用讲解片段及有依据的观察提示，不是每位游客的路线。用户换兴趣或改路线时，规则选择已发布片段，配合已审核模板排列；推荐理由描述偏好匹配，不增加历史判断。不能随意截断否定、年代范围或引文限定语。AI 新写、总结或实质改写的内容另存草稿，经来源校验与人工审核发布后才可复用。观察提示必须带对象与位置依据；未知时写明，缺材料则不给具体指示。

片段保留故事版本、事实和来源依赖；读取与音频播放前重新检查。片段缓存键包含内容版本、兴趣、深度，不包含精确位置；缓存命中仍先校验来源/授权/公开状态。来源或署名变化后再次读取立刻生效；页面恢复前台及继续阅读时刷新。服务不可达时保留用户计划和到访事件，但无法复核的受控讲解、来源节选和音频停止新展示/播放；第一版不提供可长期离线绕过撤回的内容包。

### 目标与现状

目标是减少无依据内容，并使已经出现的错误可发现、可阻止发布、可追溯。不能承诺模型永不出错，也不能把“规则未发现错误”写成“历史事实正确”。

已实现：正式生成输入检查来源、故事、事实和授权；逐句引用编号、长度、隐私与具体方位依据检查；草稿审核、发布版本、来源撤回后的读取拦截；试跑预算、诊断、版本评测。缺口：来源性质没有完整传入，未对句意是否被引用支持进行分层检查；标题等附属文字也可能新增判断；管理员当前主要依靠整体核对和评分，缺少逐项疑点；改稿后的复核尚以格式/引用为主。

这轮真实试跑只是公开文字+真实供应商的隔离试验，不能等同于正式审核链已验收。五份结构通过稿存在现场身份错置、过度存疑、兴趣差异弱；两次措辞试验失败说明不能只堆提示词。

### 一、先把证据约束写清楚

在原事实/来源关联上增量保存或服务端整理：来源类别、原文或已人工核对的节选、来源版本、支持的具体说法、限定词、适用对象与时间、已确认现场定位依据。来源类型与审核状态分开：官方来源也不自动等于历史结论最终正确；对文本校对的确认也不等于对其中历史说法的确认。

复用materialKind及已审核多模态片段；普通投稿文字不根据标题、域名或AI自评自动升级为官方/亲历。新补类型缺失则unknown，按保守口吻处理；不批量回填旧记录的授权或审核。需管理员确认的类型/摘录在现有来源审核中集中处理一次，同一版本重复复用，不给每篇稿增加表单。

每项事实尽量对应一个明确判断；原claim含多项判断时，可在生成输入中拆分为可追溯子项，不回写原claim。支持性与限定词不由生成模型自行签发。没有可回溯原文时明确仅有人工摘要，不能冒称已核原文。

口吻边界：官方记载按资料转述；个人观察保留投稿者和观察时间；口述保留讲述者归属；OCR只证明材料中写了什么；图像描述只支持画面可见特征，不支持年代、真伪或现场运营信息。引用他人的“我看见”不等于允许讲解器称“我看见”。

### 二、生成方式

先选择本次兴趣可用的事实，再编排讲解。服务端给出可用事实、支持片段和允许的定位提示；不让模型自由扩大资料范围。每个事实性分句保留claim及支持片段对应，一句包含多项判断时全部对应，不能用一个引用掩盖后半句的新结论。

标题、观察提示、过渡句也检查；事实陈述、阅读建议、资料缺口区分。诸如“可以展开来源查看”由应用固定文案提供，无需让模型生成或伪装成历史引用。模型自报“有依据/高置信”只是输出数据，服务端重新验证。

材料少可输出短稿，但正常草稿仍遵守现有最低长度；完全不足时返回独立“资料不足”任务结果，不制造一份合格草稿，不放宽20字下限，不将系统缺口提示当作讲解内容。缺少建筑材料时采用通用稿并提示暂缺，不编造兴趣差异。时长只能标估算，未朗读不可声称已验证一分钟。

### 三、两层检查与三种处理

第一层处理可确定的问题：无效引用/来源失效/授权撤回、已知字段矛盾、未经支持的精确方位、超出对象范围、明确冒认现场经历、隐私与格式。逐句检查之外同时检查标题和观察提示。

第二层标记可能的问题：限定词变化、因果或传承增强、官方记载过度存疑、疑似错配对象、缺少支撑的修辞、兴趣差异不足。仅字符串相同或数字都出现，不能证明语义一致；数字必须结合对象、属性和时间含义。有明确结构化对应才硬拦，中文数词/别名/引语/近似表达不确定时交人工，避免误杀。

处理状态：
- 明确违规：保存安全失败诊断，可在隔离区查看，不进入可发布草稿。
- 待判断：保留待审稿，逐项标出句子、证据和疑点；疑点未处理不能发布。
- 规则未发现问题：仍为待人工审核，不自动发布。

合法原文引语、解释“不能称为亲眼所见”等反例也要测试；不采用见到关键词就拒绝的粗暴规则。第一版不引入第二模型裁判；以后可选语义复核只提供疑点，不能给出事实认证或绕过人工审核。

### 四、生成失败与修订

网络失败、格式失败、证据不足、疑似新增事实、长度不符分开记录。不得遇到语义失败就换供应商、联网补事实或反复重生成直到规则放行。

第一版语义问题默认交人工；可预留一次受控修订入口，明确只修报错句，不新增事实，仍重新核对来源、预算和所有输出。该入口默认不发起额外付费请求，若后续启用计入同一预算和有限尝试次数；保存初稿与修订稿便于评测。

### 五、审核与发布闭环

在现有逐句编辑区显示“讲解句子—对应事实—支持节选—疑点”。优先列出红/黄问题，通常不增加管理员逐句打勾工作。普通句子沿用整稿审核；有疑点的句子须修改、删除、补充可核证据，或在软提示误报时写明理由。硬性授权/失效来源/无效引用不可用勾选豁免。

检查结果绑定正文及标题/观察提示、引用、来源版本和规则版本的指纹。人工保存后重算；发布前服务端再次读取当前内容与授权，不能相信前端提交的“已通过”，旧检查不能授权修改后的正文。发布事务检查版本冲突。

资料更新/撤回继续沿用当前公开读取校验；缓存命中也核对状态和检查版本。判断本身被修正时，对受影响讲解标needsSourceReview，保留历史审计并停止公开读取正文、观察提示和语音入口，避免只隐藏来源卡片而正文仍可见。公开接口不返回审核者身份、私有原文或调试信息。

老稿保留历史人工审核记录，不默认为新版校验通过。新稿与重新编辑发布的稿件执行新门槛；已发布历史稿先做只读风险筛查，确有问题的进入复核，批量变更线上状态另行授权。不在本阶段批量迁移或下架。
